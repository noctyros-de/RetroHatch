# Public source and optional local development workspace

Open **project/** in VS Code. This directory is the complete Git repository;
its existing .git history and remote configuration are preserved. Do not open
or initialize another repository in the parent workspace. VS Code discovers
app/Cargo.toml through .vscode/settings.json; Check, Test and Build release tasks
run from app/. Root AGENTS.md contains public, non-sensitive project instructions.

```text
<workspace>/
  project/                 # Git root; independently buildable public source
    .git/  .github/  .vscode/
    app/  docs/  developer/  LICENSES/
    AGENTS.md  README.md  LICENSE  ...
  local/                   # Outside the Git root; never distributed
    roms/                  # User-provided firmware; never required for Cargo tests
    references/            # Unmodified research/oracle checkouts
    resources/             # Original private branding PNG/ICO
    test-data/research/    # Existing private notes and diagnostic data
    builds/cargo/          # Optional Cargo target directory and oracle outputs
    releases/              # Local distribution candidates
    backups/               # Verified pre-migration backup and manifest
```

## Optional developer setup

Public clones and GitHub Actions need no local/ directory or extra configuration.
The ordinary commands remain unchanged:

```powershell
cd app
cargo fmt --check
cargo check --locked
cargo test --locked
cargo build --release --locked
```

For an external build cache, run from the source root:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File app/tools/configure_local.ps1
```

This creates only an ignored .cargo/config.toml and optional sibling directories.
It selects local/builds/cargo through Cargo's supported build.target-dir setting;
CARGO_TARGET_DIR still overrides it. Existing different configuration is never
overwritten. Do not copy the local config into a public checkout/source archive.
The source packager creates its own vendored-dependency configuration instead.
The setup script also accepts -LocalRoot for a different private workspace.

Optional environment overrides:

| Variable | Purpose |
| --- | --- |
| RETROHATCH_LOCAL_DIR | Private root; defaults to the source root's sibling local/ |
| RETROHATCH_REFERENCES_DIR | Python oracle/extractor reference root |
| RETROHATCH_RESOURCES_DIR | Build-time directory containing retrohatchicon.ico |
| RETROHATCH_ROM_DIR | Initial ROM import directory; no model inference |
| CARGO_TARGET_DIR | Standard Cargo output override, also respected by tooling |
| RETROHATCH_DATA_DIR | Explicit runtime settings/library/save override for isolated testing |

For a custom private root, set RETROHATCH_LOCAL_DIR in the shell as well when
running Python directly; Cargo's [env] configuration applies only to Cargo's
child processes. Relative path overrides are resolved against the caller's cwd;
absolute overrides are recommended. None of these paths is a publication input.

Firmware import copies remain in the established Windows LocalAppData library.
Settings and existing save identities/formats remain unchanged. Pictures-based
screenshots/recordings also remain in their established known-folder locations.
Existing saved import-folder preferences are preserved; an absent old folder
falls back to the new developer ROM directory. Reimporting moved original ROMs
is not required for internal library copies. Choose the new path once for any
external shortcuts or explicitly configured legacy data-root overrides.

## Tests, reference sources and distribution

All 23 synthetic fixture files (39,364,050 bytes in the migration baseline) are
retained byte-for-byte. They are not firmware dumps: Rust tests and independent
Python/C oracles use them to check CPU, MCU and device behavior. The largest
files exercise loads, branches, stack and subroutines, including full state and
memory changes. No unused or byte-identical duplicate fixture was identified.
Several ALU matrices already combine many operands per record. Replacing these
independent expected results with expectations generated by the implementation
under test would weaken regression coverage. No cases are removed for size.

Python comparison/extraction tools read ../local/references by default. They do
not edit upstream sources, and diagnostic compilation uses Cargo's configured
target directory. Standard Cargo tests rely only on committed synthetic data;
Python, Qt, external reference checkouts and proprietary ROMs are not required.

The release workflow checks out project contents as its repository root, so its
app/ and dist/ paths do not change. Locally, package_release.py defaults to
../local/releases if the optional local directory exists; --output overrides it.
It resolves the executable location through Cargo metadata and excludes the
local config and all private roots. Clean public checkouts retain app/target
and dist defaults. Packaging drafts still require --allow-dirty and --offline
can be used with the cached dependency sources. Draft packaging never publishes.

The physical workspace move does not shrink Git history: no history rewrite,
source deletion, version bump, tag change, commit or push is part of migration.
Keep license texts, source, generators, public logo and owner-selected gallery.
Review any future fixture compression separately with complete round-trip and
oracle validation rather than introducing a new build dependency for cleanup.
