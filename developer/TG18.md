# On/Meets integration

Current status (11 November 2026): the six Japanese Meets editions are now
individually firmware-tested, with dedicated profiles, full SHA-256 identities
and backward-compatible legacy saves. See [Meets validation](MEETS.md). English
On working use remains owner-reported; this iteration does not newly certify
every English revision. Bluetooth and infrared remain unavailable. Historical
synthetic integration tests below retain their original scope.

The MIT Rust core from oreo-fox/tg18-emu is a library dependency under
`app/third_party/tg18-core`, with its original license and a source hash inventory.
RetroHatch supplies the host adapter, worker, existing UI and private library.
There is one executable and one window; no upstream frontend or artwork is used.

## Implemented path

- Import an exact 8-MiB `SPII` flash dump through File > Import ROM.
- Identify the nine known On/Meets revisions using the upstream FNV-1a code
  fingerprints. Record full-image SHA-256 locally for content/save identity.
  The six verified Japanese images additionally have full SHA-256 catalogue entries;
  ambiguous content requires model confirmation once. No
  full-image SHA-256 identities were invented and filenames are not evidence.
- Start from My Tamagotchis. Render the actual 128x128 RGB565 framebuffer as
  RGB, with nearest-neighbor sampling and the current LCD-only display-scale setting.
- A/B/C use Left/Down/Right arrows and the existing mouse/letter/number controls.
  The reference GPIO pins are 0x15/0x16/0x17. Quick taps last at least 50 ms,
  matching upstream's handling of the firmware debounce. Up has no effect.
- Run/pause/reset use the existing worker and menus. Reset is a hardware
  restart retaining modified flash and RTC, as in TG18. Deep sleep advances
  RTC and wakes on scheduled alarms or an A/B/C press; alarm-only wake keeps
  the backlight off. No stock game screen or approximate artwork is generated.
- Audio uses TG18 timer events and its phase-continuous, integrated square-wave
  synthesizer at 44,100 Hz, then the existing WinMM output and mute/volume policy.
- Three slots, autosave, import/export and Save on Exit use the existing atomic
  write/backup pipeline, ROM SHA-256 and a distinct profile/backend schema.
  Capture is coherent; compression and writes run on the I/O worker. The
  snapshot extends upstream's omitted peripheral/input/audio state and stores
  flash as a delta requiring the original ROM. Existing classic states are unchanged.

## Limitations and validation boundary

The original integration had no real-firmware test. That historical limitation
is superseded for the README's current availability status by owner-reported
working use, not by a new boot measurement in this audit. Do not infer that all
upstream variants, full lifetimes, audible notifications or performance cases
were independently tested. SOME is unsupported.

Synthetic tests cover ARM execution against the reused core, actual LCD command/
data writes and RGB565 decoding, GPIO/debounce/releases, 60 emulated seconds of
sleep RTC, wake/reset with retained flash, audio/state continuation, integrity
and wrong-ROM rejection, library persistence and worker save/restart/resume.
They contain only independently authored test instructions, never firmware.
The common pacer never accelerates the device clock to hide a slow interpreter.
The reused timing model counts executed/skipped instructions; detailed E0C6200
cycle/profiling counters are not applicable to ARM and are not fabricated.

Bluetooth/infrared hardware is not emulated. The worker stops those operations
and restores the pre-input snapshot where available, with a visible error.
Resume returns to offline play. State files are RetroHatch `.rhstate` containers;
standalone TG18 `.t18s`/`.flash` files are not directly imported. Closed-app time
does not advance, and there is no background pet growth.

## Maintenance

Run the normal locked Cargo checks and the focused `host::emulator::tests` suite.
The copied upstream core's tests can also run with `cargo test --locked -p tg18-core`.
The independent classic Python differential checks still use private references.
Update license evidence after dependency changes; retain the MIT notice in
binary/source packages. No firmware, personal save or library index belongs in Git.


## Integration verification (2026-11-10)

- `cargo fmt --check`, `cargo check --locked`, `cargo test --locked` and
  `cargo build --release --locked` succeeded with the Windows MSVC toolchain.
  All 154 RetroHatch tests and seven additional copied-core tests passed.
- The existing classic CPU/MCU/device Python differential checks and 8,776-sample
  buzzer comparison passed. Eight packaging tests and the 106-package Windows
  license inventory check passed. The original TG18 source hashes and exact
  copied MIT license were verified; references were not edited.
- The release EXE was launched and closed twice with temporary user data and
  an independently authored ARM test program. It imported through the existing
  library, drew a complete red framebuffer through the actual LCD MMIO, and
  reopened its saved device in the same RetroHatch window. The saved nominal
  emulated clock advanced from 3.0530 to 6.0273 seconds across the two sessions.
  Both save checksums, profile/schema identity and flash-delta contents passed.
- The synthetic idle-loop run measured 99.995% to 99.997% average real-time
  speed over approximately two seconds. This is a host integration smoke test,
  not an On firmware/gameplay throughput measurement or a 60-second wall test.
- The release EXE imports only Windows system DLLs and contains none of the
  checked private build-root prefixes. No standalone TG18 frontend was built.

The original tests above did not run real On/Meets firmware. Current working
use is owner-reported, as stated at the top; no new gameplay/performance test
was performed in this documentation audit. Existing personal saves/libraries
were not used by those native tests. No firmware or save is part of Git.

## Keep Screen Awake ? 0.10.1 validation (13 November 2026)

The existing preference now reaches `Machine::never_sleep` for On and all six
Meets profiles; it remains disabled by default. A sleeping device receives one
normal cold wake with current flash and RTC retained, without key injection.

The failed earlier transition restored the firmware's RTC-background
`SleepFlag=2/3`, which requested power-down before the next periodic idle reset.
A literal/diagnostic-read signature now identifies that separate SRAM display
flag uniquely. While enabled, the core keeps it in the awake state and executes
the original firmware, LCD writes, interrupts and existing minute-refresh path.
Disabling removes the override. No cached frame, synthetic key or reset loop is
used. The original idle-counter mechanism is unchanged.

An optional `rh-awake-clock` snapshot chunk preserves idle-reset, minute-refresh
and idle-probe wait phases. Legacy snapshots without it still load; schemas,
ROM identities and save directories are unchanged. Exact continuation exposed
the previously omitted idle-probe phase, now covered by regression checks.

Actual unchanged private firmware: On Magic EN v058; Meets Fairy JP v030,
Magical JP v031, Fantasy JP v047, Pastel JP v055, Sanrio JP v056, Sweets JP v062.
Each passed 180 seconds awake from the active state, then 180 seconds after a
sleep-to-awake transition, normal timeout after disabling, live input, exactly
5,898,240 RTC ticks per 180 seconds and byte-exact save continuation. Normal
initial timeout was 28?29 seconds; post-input timeout was 41?49 seconds. Cold
wake first displayed pixels after 1?3 emulated seconds of normal initialization.

All seven also passed two native Windows launches with visible LCD, persisted
Keep Awake preference and advancing restored saves. The real Fairy worker
passed all three slots, import/export, automatic/exit save and fresh-worker
resume: 65.083 emulated / 65.015 wall seconds with Windows PCM output, zero drops
and zero empty-queue events. Firmware and original save hashes remained intact.

Reproduce the focused firmware test with
`cargo run --release --locked --example tg18_awake -- ROM NEW_PRIVATE_OUTPUT RESUME_STATE`.
Private evidence is in `local/test-data/tg18-awake-20261113/`; never package it.
On Fairy/Wonder Garden are recognized by the shared backend but were not locally
available for this iteration's individual firmware validation. Wireless remains
unsupported; this change does not establish new connectivity or lifetime claims.

Final local checks: 239 application tests passed (one intentionally ignored
