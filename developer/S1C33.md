# Native S1C33: Tamagotchi P's and original iD

The Rust port of maragotchi/tamaemu at
`79e19b65a1c970b9e1cd0b58ee6e929507257234` runs the locally supplied P's firmware.
`UPSTREAM.json` retains the original source hashes and attribution. No reference
files are modified, and no firmware or user saves are included in the source.

## Hardware and integration

The `ps` board maps 8 MiB NOR at 0x02000000, reset TTBR 0x02400000, 32 KiB A0RAM,
12 KiB IVRAM at 0x80000 and 4 KiB DSTRAM at 0x84000. The reference documentation
says 2 KiB DSTRAM; the actual C code and tests use 4 KiB. OSC3 is 18.432 MHz.
Firmware-driven SCCR/PLL/OSC1 32768 Hz selection, clock protection, six timers,
priority/flag/W1C interrupt control, active-low P00/P01/P02 buttons, healthy
battery ADC, BCD RTC/calendar/cyclic IRQ and SLP/HALT/wakeup are implemented.
Peripheral ticks follow the reference's 256-cycle boundary; time derives from
MCLK rather than the UI refresh. No RTC acceleration or firmware patch is used.

The existing CPU/NOR/LCD implementation is retained. The LCD has 132x162 GRAM,
a 128x128 visible panel, RGB565/RGB666, BGR/inversion, windowing and standby.
T0 tone changes are timestamped at the actual CPU write cycle, rendered as the
reference square wave at 44.1 kHz with continuous phase, and sent through the
existing Windows audio/volume/mute path. T2 diagnostic latches are retained;
the upstream desktop frontend itself outputs T0, not a separate T2 synth.
Disconnected IR TX completion/status follows the reference; no peer is invented.

The P's profile uses the existing ROM library, clean model-name menu, A/B/C
controls, pause/resume/reset, color display, slots, import/export and autosave.
Left/Down/Right map to A/B/C; Up has no gameplay effect. Known tested firmware
has a verified SHA-256 association. Unknown 8-MiB images require a valid matching
reset vector and one-time explicit model confirmation; size/name alone are not
unique identification. Existing classic and On/Meets save identities are intact.

Settings offers an optional **Keep screen awake** policy for P's and iD, disabled by
default. Normal black-screen standby and OSC1 clock reduction follow firmware.
See [UI_AUDIO.md](UI_AUDIO.md) for reference evidence and the override's scope.

## Saves and integrity

The `RTHSTATE` envelope version remains 1. P's uses device code 7 and backend
schema 3, including CPU registers/flags/prefix/halt state, complete mutable NOR,
all RAM, LCD GRAM/command/pending-pixel latches, timer accumulators, CMU, GPIO,
interrupts, RTC fractions, emulated time and audio phase/cursor/pending PCM.
Fields are explicitly encoded little-endian, with ROM/profile/schema/length,
SHA-256 and bounded structural validation. Restore builds a fresh machine;
failure leaves the running device and existing saves intact. Existing atomic
storage/backup rules apply. Snapshot encoding/hashing stays off the CPU worker.
Original imported firmware and the user's source ROM are never overwritten.

Upstream `.sav` is a full mutable NOR image, including firmware. `.tamasave` is
a versioned `TAMASAVE` record container (DEV/SAV/RAM/META, CRC32), optionally
containing a native STAT snapshot. Raw `TAMASTAT` contains C structures and
process/build-specific fields. Neither format is interchangeable with `.rhstate`.
Import/export of these upstream formats is not implemented or offered in the UI.
RetroHatch states also contain firmware bytes and must remain private.

## Verification

The real P's ROM was booted without modifying its contents. A 20-second run
with B at 8 s, A at 13 s and B at 15 s was compared against unchanged upstream
CPU/memory/LCD/peripheral code. All 20 checkpoints agree exactly in PC, cycle
count, RAM, I/O, complete GRAM, IRQ count, LCD commands and T0 event count.
The run produces color graphics, accepts button edges, changes menus and writes
857 flash programs after one sector erase. These counts describe this specific
test sequence, not a claim about every game action or device lifetime.

The native run captured 882,000 PCM samples over 20 seconds, with audible
notification data. Full-state round-trip and 10,000 further CPU steps produce
identical state/PCM before and after restoration. A separate 60-second run through
the actual host worker and Windows PCM output measured 60.022 s wall time and
60.081 s emulated time (published snapshots have about 100 ms granularity),
with zero discarded audio blocks. It imports through the actual private library,
checks Slot 1, save import/export, Save on Exit and a fresh worker's automatic
resume, while verifying that the original ROM hash is unchanged. This test uses
an isolated private temporary library rather than replacing the user's library.

The initial 1,889 synthetic C CPU/memory/NOR/LCD cases remain regression coverage.
Focused tests add CMU protection/clocks, buttons, six timers, ADC/RTC and complete
state continuation/corruption rejection. Opt-in firmware tools (never normal
Cargo tests) are:

```powershell
cd app
cargo run --release --locked --example s1c33_boot -- "../../local/roms/Tamagotchi Ps.bin" 20 "../../local/builds/cargo/ps.ppm" "8:2,8.12:0,13:1,13.12:0,15:2,15.12:0" "../../local/builds/cargo/ps.pcm"
cargo run --release --locked --example ps_validation -- "../../local/roms/Tamagotchi Ps.bin" 60
```

The optional `app/tools/compare_s1c33_boot.py` runs the same local image and button
schedule against unchanged C sources in a test-only headless adapter. It can
assert native checkpoint logs and compare captured PCM against C tone events.
It does not build or launch an upstream product frontend. Stored regression
fixtures contain synthetic instructions only; no firmware-derived snapshots,
screenshots or audio are committed. Native Windows release inspection confirmed the 128x128 firmware graphics,
A/B/C input, firmware standby/wakeup and resumption after normal close/reopen
without command-line arguments. The inspected session resumed the ROM's existing
pet, then showed its letter/cutscene; this is not an exhaustive gameplay claim.
All 882,000 captured samples match the C T0 events exactly (zero differences).
Final checks: cargo fmt --check, cargo check --locked, cargo test --locked
(168 passing, one existing interactive browser test ignored), all existing
Python CPU/MCU/model/buzzer regressions, the 1,889-case C oracle, eight archive
tests and the optimized static-runtime Windows release build pass.

## Remaining limits and other boards

Basic local boot/input/display/audio/save validation is not an exhaustive playthrough.
Infrared connections, downloadable content, PN512/NFC, speed controls, upstream
save conversion and cross-process/native-C exact-frame snapshots remain absent.
Unknown/reserved/debug/coprocessor operations still fail explicitly; errors roll
back CPU/bus effects. The source's silently ignored coprocessor operations are
deliberately rejected rather than reported as functional hardware.

Internal maps remain available for 4U/4U+ (8 MiB, 30 MHz, PN512). Upstream key `4u` means 4U+; `4u-plain`
means 4U. These remain unexposed without actual firmware validation.
The shared core now also serves original iD, Lovely Melody and the tested iD L
editions; see [ID_FAMILY.md](ID_FAMILY.md). Normal sleep/wake works on all tested
boards. The optional keep-awake override is unavailable on Princess Spacy and
15th Anniversary because their firmware RAM marker has not been established.

## Original Japanese iD integration

The existing `id` hardware profile now uses the same CPU/peripheral/LCD/backend
as P's. See [iD validation and revision limits](ID.md). The device has a distinct
ROM-library identity and save profile code 8; P's retains code 7 and its existing
schema/payload. Further verified iD-family profiles append codes 9 through 13 without changing these existing identities.
The local `s1c33_boot` example accepts `--hardware id`, `--state PATH` and
`--resume PATH`. `ps_validation ROM 60 --profile id` reuses the production
worker/audio/library/save/reopen checks; its default remains P's.

## Plus Color family

Plus Color and Hexagontchi now use the existing 20-MHz board profiles through the
same host worker, library, color LCD, PCM and schema-3 saves (codes 14/15).
See [PLUS_COLOR.md](PLUS_COLOR.md) for actual firmware validation, debug-strap
polarity, top-boot NOR, clock-aware reference comparisons and keep-awake limits.
No CPU, timer, flash or audio algorithm was changed for this integration.
